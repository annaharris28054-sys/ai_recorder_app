# 录音机 APP 项目理解

基于 `sheji` 文件夹内文档与 5 张原型图的综合理解。

---

## 一、项目是什么

这是一款 **AI 智能录音机** 移动应用：在高质量录音的基础上，提供**转写**、**AI 总结**（标签 / 核心结论 / 待办）、**多发言人识别与打点**，面向会议、访谈等场景，把录音变成可检索、可回顾的智能记录。

产品有两种技术路线文档并存：
- **PRD + development**：偏 **纯本地 / 离线优先**（Flutter + 端侧 Whisper + 本地 LLM/GGUF），强调隐私、无后端。
- **PRD 的 AI 指南**：也允许云端 API（Groq/DeepSeek/Kimi）做转写与总结，开发时可二选一或分阶段实现。

## 三、核心功能理解

| 模块 | 要点 |
|------|------|
| **录音与打点** | 大麦克风进入录音；支持暂停、停止；「打点」记录当前时间戳，后续与转写段落关联，在全文转写里以「手动打点」展示。 |
| **转写** | 录音结束后后台转写（或端侧 Whisper）。结果带时间戳、发言人（声纹/角色名）；支持「AI重点」与「手动打点」两种高亮。 |
| **AI 总结** | 基于全文转写生成：标签 (tags)、核心结论 (conclusions)、待办 (todos)；可选用「自定义总结模板」作为 Prompt 前缀。 |
| **搜索** | 匹配标题 + 转写/总结全文，即「搜索文件名或转写内容」；列表可展示命中片段上下文。 |
| **播放与联动** | 倍速、退/进 15s、打点；播放时转写列表需随当前时间滚动并高亮对应句。 |
| **设置** | 多模式降噪（关/智能/深度）→ 下次录音生效；总结模板管理；专属词库 → 转写时作 hotwords/prompt 提升准确率。 |

## 四、设计规范（来自 UI.md）

- **主色**：`#4C4DDC`（深紫蓝），用于主按钮、选中态、关键图标。
- **录音页背景**：`#15162B`（深色沉浸）。
- **列表/设置背景**：`#F5F7FA`；卡片 `#FFFFFF`。
- **语义色**：停止 `#FF4D4F`，成功 `#00C48C`，待办/提示 `#FF9F43`。
- **布局**：8px 栅格，左右 16px 边距，大圆角（如 16px），录音主按钮圆形突出。

设计思路.md 中的 React 原型用 indigo 系，与 UI 文档的 `#4C4DDC` 属同一色系，开发时以 UI.md 为准即可统一。

---

## 五、数据与存储

- **PRD**：账号仅做本地校验，所有录音/转写/总结按 `user_id` 隔离，不上传云端。
- **核心实体**：User、Record（录音元数据 + 文件路径 + 状态）、Transcript（带时间戳与 tag_type）、AISummary（tags/conclusions/todos 的 JSON）、Vocabulary（专属词库）。
- **development.md**：采用 Isar 存录音与转写，SharedPreferences 存降噪/模板等设置；Flutter 方案中录音用 `record`，播放用 `audioplayers`，波形用 `audio_waveforms`。

## 七、总结

项目目标清晰：**按 5 张原型图 + 设计思路.md 做界面与交互**，按 **PRD + UI.md** 做产品逻辑与视觉规范，按 **development.md**（若选 Flutter 离线方案）做架构与实现顺序。  
核心价值是：**录音 → 转写 → AI 总结 → 可搜索、可打点、可回放**，并支持降噪、词库、总结模板等个性化设置，在会议/访谈场景下把「录下来」变成「用得起来」。
